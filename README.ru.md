# Jarvis

Десктопный AI-ассистент для Windows. Jarvis — это небольшая сфера поверх
других окон, которая разворачивается в полноценную консоль чата: он общается с
выбранной вами моделью, выполняет инструменты на вашей машине (файлы, shell,
поиск, анализ диска) и хранит собственную память и историю переписки.

**Статус: v0.1.0-beta.1** — открытая бета. Всё работает, но шероховатости
ожидаемы; сообщения об ошибках приветствуются.

> English version: [README.md](README.md)

---

## Что умеет

* **Чат со стримингом** — несколько провайдеров и моделей с переключением на
  лету: OpenAI, Google, Groq, OpenRouter, NVIDIA NIM и любой
  OpenAI-совместимый эндпоинт.
* **Два агента**
  * *assistant* — общие запросы, веб-поиск, память, буфер обмена, чтение,
    запись и правка файлов, команды shell;
  * *code* — работает внутри папки-воркспейса: читает и правит файлы, ищет по
    содержимому, планирует многошаговые задачи, вызывает git и shell, ищет в
    интернете.
* **Локальные инструменты на вашей машине** — нативный сканер диска (Rust) для
  вопроса «куда ушло место», индекс имён файлов по всему диску, запуск команд
  и файловые операции. Всё это делает локальный Python-бэкенд.
* **Память и история** — долговременные заметки, переписки, трассы запусков и
  прогресс фоновых задач. Всё переживает перезапуск.
* **Два окна** — компактная сфера, которая не мешает, и консоль с чатом,
  телеметрией и настройками.

Интерфейс и комментарии в коде двуязычные (русский и английский); язык
интерфейса соответствует строкам, зашитым в сборку.

---

## Требования

* Windows 10 или 11, x64.
* API-ключ хотя бы одного поддерживаемого провайдера. Jarvis не поставляет
  ключи и не проксирует трафик: запросы идут с вашей машины напрямую
  провайдеру.
* Python и Node.js не нужны — установщик несёт собственный интерпретатор.

## Установка

1. Откройте [Releases](../../releases) и скачайте последний
   `Jarvis_*_x64-setup.exe`.
2. Запустите его. Установщик ставится в профиль пользователя, права
   администратора не нужны.
3. SmartScreen предупредит о неизвестном издателе — бета не подписана
   кодом. Нажмите **Подробнее → Выполнить в любом случае**.

**Автообновления нет.** Чтобы обновиться, поставьте новый релиз поверх
старого: данные в `%APPDATA%` сохранятся. Удаление программы не удаляет ваши
данные.

### Первый запуск

1. Откройте окно настроек и вставьте API-ключ провайдера.
2. Выберите основную модель.
3. По желанию выберите папку-воркспейс — подсказку агенту, где обычно лежит
   ваш проект. Значения по умолчанию нет; агент может читать и писать там,
   где этого требует задача.

## Где лежат данные

Всё, что записывается, живёт в одной папке пользователя:

```
%APPDATA%\com.jarvis.assistant\
  api_keys.json          настройки и API-ключи
  conversations\         история переписок
  traces\                трассы запусков агента
  uploads\               вложения из чата
  _file_index\           индекс имён файлов по диску
  cache\                 кэш анализа диска
  memory_store.json      долговременная память
  tasks_history.json     журнал фоновых задач
  location_cache.json    кэш геолокации
  backend.log            лог Python-бэкенда (первое место при ошибках)
```

Папка установки считается только для чтения. **Воркспейс** — необязательная
подсказка, где лежит «проект»: значения по умолчанию у неё нет, и она ничего
не ограничивает — файловые инструменты и shell агента могут работать там, где
этого требует задача. Обе папки можно переопределить переменными окружения
`JARVIS_DATA_DIR` и `JARVIS_WORKDIR`.

## Безопасность

Jarvis — локальное приложение, и компромиссы здесь обычные для локальных
приложений:

* Бэкенд слушает только `127.0.0.1:8765`, в сеть он не выставлен.
* При каждом запуске Rust-оболочка генерирует случайный токен и передаёт его
  бэкенду; UI прикладывает его к каждому запросу. Чтобы вызвать API, другой
  программе нужно знать этот токен, а сайт из браузера не может этого сделать
  вообще (CORS разрешён только для origin приложения).
* API-ключи лежат в открытом виде в `api_keys.json` в вашем профиле.
  Интеграции с системным хранилищем секретов пока нет.
* Агент умеет читать и писать файлы, запускать команды и ходить в сеть.
  Просьба вставить секрет в чат — повод насторожиться.

## Сборка из исходников

Что нужно:

* Node.js 18+ и npm
* Rust (stable, toolchain MSVC) с рабочей нагрузкой **Desktop development with
  C++** из Visual Studio Build Tools
* Python 3.10 x64 (только для тестов и сборки встроенного бэкенда)
* Git

```powershell
git clone https://github.com/w99zzl1/Jarvis.git Jarvis
cd Jarvis
npm install
npm run tauri:dev
```

`npm run tauri:dev` поднимает Vite, компилирует Rust-оболочку и запускает
приложение; в dev-режиме оболочка берёт `python` из `PATH` и запускает
`server/main.py`.

### Сборка установщика

```powershell
# 1. Собрать Python-бэкенд: embeddable CPython 3.10 + зависимости
powershell -ExecutionPolicy Bypass -File scripts\build_backend.ps1

# 2. Собрать нативный сканер диска (Rust/PyO3) в подготовленный бэкенд
powershell -ExecutionPolicy Bypass -File scripts\build_disk_scan.ps1

# 3. Собрать приложение и установщик NSIS
npm run tauri:build
```

Результат появится в `src-tauri\target\release\bundle\nsis\`.

`scripts\build_backend.ps1` скачивает embeddable-дистрибутив CPython в
`.cache\`, ставит в него закреплённые версии зависимостей из
`requirements.txt` и копирует исходники бэкенда в `backend-dist\backend\`.
Tauri поставляет эту папку как ресурс, и Rust-оболочка запускает бэкенд уже
оттуда. В систему ничего не устанавливается.

## Структура проекта

```
src/                  UI на React + Vite (сфера, консоль, настройки)
src-tauri/            Rust-оболочка: окна, конфиг, жизненный цикл бэкенда, health
server/               бэкенд FastAPI: маршруты, стриминг, переписки
agents/               assistant- и code-агент и их наборы инструментов
shared/               пути, LLM-клиент, память, индекс файлов, задачи, анализ диска
native/jarvis-disk/   сканер диска на Rust, доступный из Python через PyO3
config/               промпты агентов и конфигурация инструментов
scripts/              сборка бэкенда и нативного модуля
tests/                проверки на чистом Python (pytest не нужен)
backend-dist/         генерируется: подготовленный бэкенд для установщика
```

Бэкенд слушает только `http://127.0.0.1:8765`. Его запускает и останавливает
Rust-оболочка, а состояние показывается в окне сферы (`STARTING BACKEND` /
`SYSTEM ONLINE` / `BACKEND OFFLINE`).

## Если что-то не работает

**`BACKEND OFFLINE` в окне сферы.** Текст под заголовком объясняет причину.
Откройте `%APPDATA%\com.jarvis.assistant\backend.log` — traceback Python
пишется туда, потому что у собранного приложения нет консоли.

**Антивирус что-то удалил.** `backend\python\python.exe` — обычный
embeddable CPython. Некоторые сканеры не любят неподписанные exe внутри
установщика; восстановите файл или добавьте исключение и откройте Jarvis
заново.

**«Port 8765 is already used by another program».** Порт занят другим
процессом (часто это зависший бэкенд Jarvis). Закройте его и откройте Jarvis
снова.

**Не загружаются модели.** `/models/live` запрашивается у провайдера при
старте бэкенда; при отсутствующем или неверном ключе список будет пустым.
Проверьте ключ в настройках и ошибку провайдера в логе.

**Сбросить всё.** Закройте Jarvis и удалите `%APPDATA%\com.jarvis.assistant`.
Вместе с настройками пропадут переписки и память.
